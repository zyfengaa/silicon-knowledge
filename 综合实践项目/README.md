## 建议路线

- **体系结构模拟线（01 → 02 → 04 → 05）**：从 CPU 流水线到缓存、脉动阵列和 TPU MXU，重点是周期级建模与"计算 / 访存"账目闭合。先做 01/02 打基础，再做 04/05。
- **性能工程线（03 → 06）**：先写 CUDA kernel 并用 profiler 找瓶颈，再用 Roofline 分析真实程序；03 需要 NVIDIA GPU，06 可在 CPU 上完成。
- **芯片物理与经济线（07 → 08）**：用 SPICE 理解器件 / 电路层面的延迟与功耗，再用良率与成本模型理解"为什么大芯片贵"。这两项不依赖前两条线。

## 通用交付规范

每个项目至少包含：

- `src/` 或等价源码目录，以及一条可复现的构建 / 运行命令；
- `tests/`：至少覆盖正常路径、边界条件和一项手算 / 参考实现对照；
- `results/`：原始数据（CSV / 日志）与图表，不接受只有截图没有数据；
- `report.md`：实验设置、方法、结果、误差来源、局限与参考；
- 根目录 `README.md`：环境、依赖、运行步骤、输出说明。

验收强调**可量化**：周期数、命中率、吞吐、误差、成本都要有数字和口径。硬件规格数字以 [SPECS.md](../SPECS.md) 为基线，并注明单芯片 / 板卡 / 系统口径；成本类数字标注年份、币种与"示例假设"。
