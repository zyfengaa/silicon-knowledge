# 项目 04 — 脉动阵列 GEMM 模拟器

> 用周期级二维脉动阵列模拟器，跟踪每个 PE 每一拍的输入、累加与输出，并比较 WS / OS（可选扩展 IS）数据流。

## 目标

- 把矩阵乘映射到 R×C 的 PE 阵列，理解数据在阵列中的流动与复用。
- 显式建模权重预装、波前（skew）、填充（fill）、计算与排空（drain）。
- 用周期数、PE 利用率和数据复用次数比较不同数据流的取舍。
- 分清"数值正确"与"时序正确"：两者都必须验证。

## 任务要求

**必做**

1. Python 3.10+（numpy 仅用于参考结果）实现 R×C 脉动阵列，R、C 可配置（4×4、8×8、16×16、32×32）。
2. 输入 `A[M,K]`、`B[K,N]`，输出 `C[M,N]`；支持 M/N/K 不是阵列尺寸整数倍时的分块与补零。
3. 实现 **WS（Weight Stationary）** 与 **OS（Output Stationary）** 两种数据流：
   - 数据在 PE 间逐拍传递，不能"瞬间广播"；
   - 明确每拍每个 PE 的 `a_in`、`b_in`、`acc`、`a_out`、`b_out`；
   - 画出每个数据流的权重 / 激活 / 部分和流向箭头。
4. 实现波前偏斜（skew），使数据在正确周期到达正确 PE；记录预装、填充、计算、排空各占多少拍。
5. 输出小规模（2×2、4×4 阵列）的逐拍 trace：cycle、PE 坐标、输入、累加值、输出、是否有效 MAC。
6. 统计：总周期、有效 MAC 数、PE 利用率 = 有效 MAC / (R×C×总周期)、实际吞吐（FLOP/cycle）与理论峰值 `2RC` FLOP/cycle。
7. 对 WS 与 OS 各 100 组随机尺寸（1 ≤ M,N,K ≤ 64）做 int8 输入 / int32 累加的精确校验。

**可选扩展**

- 增加 IS（Input Stationary）数据流并纳入三方对比。
- 双缓冲 / 权重预取，允许预装与计算部分重叠（必须单独报告重叠口径）。
- 按 SRAM 端口与容量建模带宽，统计每层 buffer 的读写次数。
- 支持 4×4 分块（tile）并分析 tiling 对利用率和复用次数的影响。

## 里程碑

- **M1 骨架**：矩阵乘功能正确（可先不建模时序），算好参考结果。
- **M2 核心**：WS 的预装、偏斜、逐拍传递、排空；2×2 手算 trace 对齐。
- **M3 验证**：OS（若做 IS 扩展则一并验证）、分块与补零、100 组随机精确校验、周期账目闭合。
- **M4 报告**：数据流对比、阵列尺寸扫描、利用率与复用分析。

## 交付物

- `src/`：阵列模型、数据流调度器、trace 输出；`tests/`：随机校验与手算用例。
- `traces/`：2×2 与 4×4 的逐拍 trace（限制规模，避免文件爆炸）。

## 验收标准

- 2×2 阵列、2×2×2 GEMM 的逐拍 trace 与手算表 **每拍、每 PE 完全一致**，包括无效拍。
- WS 与 OS 各 100 组随机 int8 GEMM 输出与 numpy 参考 **逐元素精确相等**（int32 无溢出）。
- 周期账目闭合：预装 + 填充 + 计算 + 排空 = 总周期，误差 0 拍；重叠模式需给出分解公式。
- WS 与 OS 两种必做数据流均实现；若完成 IS 扩展，则三者对同一 64×64×64 问题输出一致，周期数、利用率和 buffer 访问次数可比较。
- 阵列尺寸 4/8/16/32 的扫描至少 4 组；解释利用率随尺寸变化的趋势（含补零浪费）。
- 报告明确"周期级"仅指模型内部时序，不含真实时钟、布线延迟、功耗或面积。

## 常见陷阱与口径

- 矩阵方向要固定：`A[M,K] × B[K,N] = C[M,N]`，PE(i,j) 负责哪个输出元素必须写清，否则转置错误很隐蔽。
- **偏斜差一拍**是最常见 bug：用 2×2 手算表逐拍核对，而不是只看最终结果。
- 预装与排空是否计入总周期、是否与计算重叠，必须统一；不同数据流不可用不同口径比较。
- PE 利用率的分母是 `R×C×总周期`，包含填充 / 排空拍；若只算计算阶段，需明确标注。
- WS 的"权重静止"指权重在 PE 内驻留，不表示权重永不加载；加载次数与 buffer 容量要报告。
- 分块时每个 tile 的累加器要清零；补零不能改变数值，但会增加周期，需计入浪费。
- trace 只对小规模输出；大规模问题用汇总统计，避免生成 GB 级日志。
