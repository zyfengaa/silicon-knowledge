# 08 — 从晶体管到微架构：PPA 如何塑造芯片

> 一句话结论：器件参数不是停留在工艺手册里的数字，它们通过标准单元的面积/延迟/电容、SRAM 的密度与 Vmin、互连的 RC 和时钟开销，逐级变成微架构的流水线深度、乱序窗口、SIMD 宽度与 Tensor Core 尺寸；所谓 PPA 取舍，本质上是在这条传导链上选择把代价放在哪一层。

---

## 为什么讲这个

前七篇从 PN 结讲到 CMOS 门、延迟和功耗，回答的是“一个晶体管/一个门如何工作”。但芯片架构师面对的不是单个晶体管，而是“在给定工艺、TDP 和面积预算下，能放多少个核、多深的流水线、多大的缓存、多宽的 Tensor Core”。这中间的翻译过程，才是器件物理真正影响系统性能的地方。

本篇把 01–07 的结论串成一条**全栈映射（Full-Stack Mapping）**：器件 → 标准单元 → SRAM bitcell → 微架构 → 加速器阵列 → 系统。重点不是重复器件公式，而是回答三个问题：PPA 三角如何约束架构选择；主频为什么停在约 5 GHz；暗硅为什么把产业推向多核与专用加速。流水线、乱序、SIMD、Tensor Core 和功耗墙的既有分析分别在 [03 流水线性能](../../03-CPU流水线/notes/05-pipeline-performance.md)、[04 乱序执行](../../04-CPU微架构进阶/notes/02-out-of-order.md)、[04 SIMD](../../04-CPU微架构进阶/notes/05-simd.md)、[06 Tensor Core](../../06-GPU架构/notes/07-tensor-core.md) 与 [11 功耗与热设计](../../11-系统分析与性能工程/notes/03-power-thermal.md)；本篇只负责把它们接回器件层。

---

## 核心概念

### 1. 五层抽象：每层只向上提供四种“货币”

从器件到系统，芯片可以分成五层。每一层都向下层索取**面积、延迟、能量、带宽**，再把这些量包装成上一层能用的接口。

| 层 | 关键参数 | 向上一层提供 |
|----|---------|-------------|
| 器件 | `Vth`、`Ion`、`Ioff`、`Cgg`、`W_eff`、`Vdd` | 驱动电流、漏电、栅电容、本征延迟 |
| 标准单元 | 单元高度、CPP、驱动档位、引脚电容 | 门级面积、延迟、功耗、噪声容限 |
| SRAM / 寄存器堆 | bitcell 面积、`Vmin`、端口数、访问能量 | 容量、带宽、访问延迟 |
| 微架构 / NoC | 流水线深度、发射宽度、ROB、缓存、拓扑 | IPC、频率、片上带宽 |
| 加速器 / 系统 | Tensor Core/MXU 尺寸、精度、TDP | 峰值吞吐、能效、成本 |

这条链有两个重要性质。第一，**约束是逐级放大的**：器件 `Cgg` 增加 20%，到标准单元可能变成输入电容和扇出延迟，到微架构就变成“这一级不能接太多负载”，最后变成流水线级数或发射宽度。第二，**架构可以隐藏但不能消除物理代价**：缓存能隐藏 DRAM 延迟，乱序能隐藏指令等待，但都要用 SRAM 面积、寄存器堆端口和功耗来换。

### 2. PPA 三角：没有免费的架构

**PPA** 指功耗（Power）、性能（Performance）、面积（Area）。性能通常写成 `IPC × f`，功耗写成 `P_dyn + P_static`，面积则由晶体管数、标准单元密度和 SRAM 密度共同决定。三者在给定工艺和 TDP 下互相拉扯：

- 加深流水线可以提高 `f`，但增加锁存器/时钟功耗、面积和分支误预测代价；
- 加宽乱序可以提高 IPC，但唤醒/选择逻辑、寄存器堆端口和 ROB 面积迅速上升；
- 加宽 SIMD 可以提高规则数据的吞吐，但标量代码利用率下降，宽执行单元和寄存器堆带宽都要付出代价；
- 增大缓存降低 miss rate，但 SRAM 面积、漏电和访问能量上升；
- 增大 Tensor Core tile 提高数据复用，但面积按 tile 边长平方增长，小矩阵利用率下降；
- 提高频率提高单线程性能，但功耗随 `V²f` 上升，还要为更高电压留出散热和供电余量。

所以架构设计不是“把每个参数都调大”，而是针对工作负载找 PPA 曲面上最合适的点。专用加速器之所以有效，是因为它改变了“算法到硬件的映射”，让同样的物理资源服务更窄但更常见的计算模式，而不是违反了 PPA。

### 3. 主频为什么停在约 5 GHz

时钟周期不是只有逻辑延迟：

```text
T_cycle ≥ t_logic + t_clk-q + t_setup + t_skew + t_jitter
f_max ≈ 1 / (N_FO4 · t_FO4 + t_overhead)
```

在 7 nm 级工艺，FO4 约 5–8 ps（2015–2020 年公开估算，随 Vdd、库和 corner 变化；见 [06 门延迟](06-gate-delay-logic-effort.md)）。若一个流水级有 20 个 FO4，逻辑延迟约 100–160 ps；再加上触发器 `t_clk-q`、建立时间、时钟偏斜和抖动约 40–80 ps，周期约 140–240 ps，对应约 4–7 GHz。这正是现代高性能 CPU 单核短时 boost 落在 5–6 GHz、全核持续频率更低的原因之一。

更深 pipeline 理论上还能提频，但每加一级都要付出锁存器面积/功耗、时钟树功耗和误预测惩罚；先进节点的长线 RC 又不随晶体管缩小，跨模块信号需要更多中继或流水级。再加上 `Vth` 和亚阈值摆幅决定的电压下限（SPECS §7.1），提高频率往往要先提高 `Vdd`，而 `P ∝ V²f` 会让功耗密度迅速撞上散热墙。5 GHz 不是物理定律，而是**时序、功耗、散热和 IPC 共同形成的平衡点**。

不同器件的选择正好说明这一点：CPU 追求单线程延迟，频率高但并行度有限；GPU 用大量 SIMT 单元换吞吐，频率通常在 1.5–2.5 GHz；TPU v4 的 MXU 以 8 个 128×128 阵列并行工作，频率约 1.05 GHz（SPECS §3），用低电压和巨大并行度换能效。

### 4. 暗硅：固定 TDP 下的“可用面积”

Dennard 缩放失效后，器件密度仍按节点上升，但电压不再同步下降，功耗密度随代际增加（见 [03 短沟道效应](03-short-channel-dennard.md)、[07 功耗](07-power-dynamic-static.md)）。在固定 TDP 和散热能力下，芯片不能同时让所有晶体管以最高频率工作，这就是**暗硅（Dark Silicon）**。Esmaeilzadeh et al. (2011) 的模型预测，按当时的多核扩展趋势，到 8 nm 级会有超过一半的晶体管无法同时全速供电；这是模型预测，不是产品实测。

暗硅的架构后果是“**少同时工作、让工作的部分更高效**”：多核在较低电压/频率下并行，专用加速器用更窄的数据通路换 10–100 倍的能效，电源门控关掉空闲模块，DVFS 按负载调整电压频率，异构 SoC 把不同任务放到最合适的单元。模块 11 从系统和散热角度展开这些手段（[11 功耗、能效与芯片热设计](../../11-系统分析与性能工程/notes/03-power-thermal.md)），本篇只强调：它们不是架构师的偏好，而是器件功耗曲线写进系统预算后的必然结果。

### 5. 器件约束如何传导到具体结构

**SRAM 密度。** 6T bitcell 由两个交叉耦合反相器和两个访问管组成，为了密度必须使用最小尺寸器件，因此对 `Vth` 随机涨落、线边缘粗糙度和读/写裕量最敏感。先进节点 SRAM bitcell 面积每代只缩小约 5–10%，而逻辑密度缩小快得多（公开估算，N5 级 bitcell 约 0.02 µm² 量级；具体数值依代工厂）。同时 SRAM 的 `Vmin` 通常比逻辑高 100–200 mV，因为读 disturb、写裕量和统计变异更苛刻。后果是缓存容量增长放缓、SRAM 占 die 面积比例上升（CPU 缓存常占 30–50%，公开估算），架构师转向更多缓存层次、压缩、显式 scratchpad 和近存计算。TPU v1 的 28 MiB 片上存储就是这种“用 SRAM 换带宽/能量”的典型（[09 TPU 架构](../../09-Google-TPU/notes/07-tpu-arch-core.md)）。

**寄存器堆与乱序窗口。** 乱序执行需要多端口寄存器堆：发射宽度 4–8 意味着每周期多次读、多次写，端口数增加会让 bitcell 面积和访问能量近似按端口数的平方增长（公开估算）。唤醒/选择逻辑、旁路网络和 ROB 也随窗口变大而变复杂。于是“更宽的乱序”不是免费的：它直接受寄存器堆面积、访问延迟和功耗约束，现代 CPU 通常停在 4–8 宽、ROB 数百项的量级（[04 乱序执行](../../04-CPU微架构进阶/notes/02-out-of-order.md)）。

**片上网络。** 晶体管缩小，但铜线的电阻率不缩小；线宽/线厚下降使电阻上升，电容下降有限，RC 延迟在先进节点反而更突出（见 [13 BEOL](../../13-工艺制造与先进封装/notes/04-beol.md)）。NoC 的缓冲区是 SRAM，链路是长线，跨电压域还要同步器；公开估算中 NoC 可占多核 SoC 动态功耗的 10–30%。因此拓扑（mesh/ring/crossbar）、链路宽度、缓冲深度和电压频率岛都要和器件/布线一起选，GPU 的 L2 切片与 crossbar、chiplet 的 UCIe 链路都是这条约束的产物（[06 GPU 互联](../../06-GPU架构/notes/08-gpu-interconnect.md)、[13 Chiplet/UCIe](../../13-工艺制造与先进封装/notes/06-chiplet-ucie.md)）。

**Tensor Core / MXU。** 矩阵单元本质上是“MAC 阵列 + 本地 SRAM + 累加/控制”。tile 边长 `N` 增大时，MAC 数按 `N²` 增长，面积也按 `N²` 增长；但每个 MAC 的数据复用次数按 `N` 增长，算术强度提高，单位计算的 SRAM 带宽和能量下降。因此大 tile 适合大矩阵，小矩阵会因利用率不足而浪费面积。精度也直接改变面积/能量：乘法器面积随位宽近似平方增长（公开估算），FP4/FP8 因此在同样面积下能塞进更多 MAC，B200 的 FP4 dense 峰值 9,000 TFLOPS 是 FP16 2,250 TFLOPS 的 4 倍（SPECS §1，dense 口径）。TPU v1 的 256×256 MXU 有 65,536 个 MAC，配合 28 MiB 片上存储和 75 W TDP，是“器件密度、SRAM 带宽、功耗”三者折中的经典样本（[06 Tensor Core](../../06-GPU架构/notes/07-tensor-core.md)、[08 脉动阵列](../../08-NPU神经网络处理器/notes/02-systolic-array.md)）。

## 深入理解

### 5 GHz 的物理账

把 `T_cycle` 拆开看，5 GHz 对应 200 ps。若 FO4 为 7 ps，200 ps 只够约 28 个 FO4；扣除触发器 `t_clk-q`、建立时间、时钟偏斜和抖动（合计几十 ps），真正留给组合逻辑的只有 15–22 个 FO4。这个深度决定了单核流水线大致在十几到二十几级：再深，分支误预测的惩罚和时钟/锁存器功耗会吃掉提频收益；再浅，每级逻辑太复杂，FO4 数超预算。模块 03 的 CPI 分解正好描述了另一面：`CPI = CPI_ideal + CPI_data + CPI_control + ...`，更深的流水线缩短周期时间、提高 `f`，却可能提高 `CPI_control`。

### SRAM 为什么比逻辑更早撞墙

逻辑晶体管可以通过 FinFET/GAA、应变、High-k 改善栅控和驱动；SRAM bitcell 却必须保持最小尺寸和规则版图，无法随意加宽或换结构。读操作要求访问管与下拉管的比例合适，写操作要求上拉与访问管的力量对比合适，降低 `Vdd` 会同时压缩读/写裕量；随机掺杂涨落和线边缘粗糙度又让最小尺寸器件的 `Vth` 分布最宽。于是 SRAM 的 `Vmin` 往往高于逻辑，缓存不能跟着逻辑一起降到最低电压。这就是为什么“逻辑密度继续提升”并不等于“缓存容量同步提升”，也是为什么大模型芯片要在 HBM、SRAM、寄存器之间做更细的层次设计。

### Tensor Core 尺寸与利用率

一个 `N×N` 的 systolic 阵列在计算 `N×N×K` 的矩阵乘时，理想情况下用 `K` 个周期完成；如果实际矩阵只有 `M×M`（`M < N`），阵列的一部分会闲置，利用率约为 `(M/N)²`。因此 Tensor Core 的 tile 越大，大矩阵的复用和能效越好，小矩阵浪费越严重。架构上通常用多个较小阵列、动态分区或不同精度的执行单元来覆盖不同尺寸；这也是为什么 GPU 的 Tensor Core 形状随代际变化，而不是简单地把一个阵列做得越大越好（[06 精度与硬件](../../06-GPU架构/notes/12-precision-hardware.md)）。

### 暗硅之后：专用化与异构

暗硅不是说晶体管坏了，而是“在散热预算内不能同时全速运行”。这给专用加速器创造了空间：同样的功耗预算，一个只做矩阵乘的阵列可以比通用核快一个数量级以上；代价是它只覆盖一部分算法，剩余部分仍要通用核或别的加速器。于是现代 SoC/GPU 走向异构：CPU 处理控制和不规则代码，GPU 处理吞吐型并行，Tensor Core/MXU 处理规则矩阵运算，DSA 处理特定领域。模块 11 的异构系统讨论（[11 异构计算](../../11-系统分析与性能工程/notes/04-heterogeneous.md)）和模块 09 的 TPU 设计，都是这条逻辑的展开。

### 从 PPA 到系统

器件约束最终会出现在板卡和机房：更高的 TDP 需要更强的供电和散热，H100 SXM 700 W、B200 1,000 W、B300/GB300 1,400 W（SPECS §1，模块级 TDP 口径）；封装热阻和冷却能力限制了芯片能持续跑在多高的频率；供电网络的 IR drop 和噪声又反过来限制电压/频率切换速度。因此“架构选择”从来不只是 die 内部的事，它和封装、散热、供电、成本一起构成系统级 PPA。14 模块的可靠性与成本模型（[14 老化](../../14-可靠性与成本模型/notes/04-aging-bti-hci.md)）会继续这条链：温度、电流密度和电压应力最终决定芯片能工作多久。

---

## 总结

- 器件参数通过标准单元、SRAM、互连和时钟逐级放大为架构约束；每一层只向上提供面积、延迟、能量和带宽。
- PPA 三角意味着没有免费的架构决策：流水线深度、乱序宽度、SIMD 宽度、缓存容量和 Tensor Core 尺寸都在互相交换代价。
- 主频停在约 5 GHz 是 FO4 时序、电压下限、功耗密度、时钟开销和散热共同形成的平衡，不是单一工艺限制。
- Dennard 缩放失效后，固定 TDP 无法点亮全部晶体管，暗硅推动多核、专用加速器、电源门控和异构集成。
- SRAM 密度/Vmin、寄存器堆端口、NoC 线延迟和 Tensor Core 面积，是器件约束进入微架构的四条主要通道。
