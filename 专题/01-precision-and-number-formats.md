# 专题 01：精度与数值格式

> 精度（precision）不是一个软件标签，而是一条从**位布局 → 指令 → 执行单元 → 累加器 → 存储与互连**的硬件通路。
> 本页只负责把这条通路上的入口串起来；完整推导见各模块笔记。

---

## 问题

- 为什么 FP16 和 BF16 都是 16 位，训练时却常常优先选 BF16？
- FP32、TF32、FP8、FP4 的位宽到底怎么分配？为什么 FP8 的峰值可以是 FP16 的两倍？
- 低精度输入是否意味着低精度累加？为什么 Tensor Core 仍普遍使用 FP32 累加？
- 为什么“硬件支持 FP8”不等于“这个型号、这个 kernel 就能跑 FP8”？
- 量化（quantization）和低精度浮点格式是什么关系？INT8 NPU 与 FP8 GPU 是同一条路吗？
- 精度变化如何改变显存占用、HBM 带宽压力和 Roofline 上的算术强度？

## 阅读路径

1. **先看位布局。** 读 [IEEE 754 论文笔记](../01-数字逻辑基础/papers/01-ieee754-standard.md)，建立符号位、指数位、尾数位、偏置（bias）、规格化与舍入的基本框架。重点不是背位宽，而是理解“指数位管范围、尾数位管有效精度”。
2. **再看硬件通路。** 读 [06-12 精度与硬件](../06-GPU架构/notes/12-precision-hardware.md)。这是本专题的主干：它把 CUDA Core、Tensor Core、SIMD、AMX、TPU/NPU MAC 阵列放进同一条因果链，并解释为什么窄位宽能换来更高吞吐。
3. **看量化如何把浮点变成整数。** 读 [08-04 神经网络量化](../08-NPU神经网络处理器/notes/04-quantization.md)，理解仿射量化、校准、QAT、BF16/FP8，以及 INT8 乘法器在面积和能耗上的优势。
4. **看一个真实加速器的选择。** 读 [09-07 TPU 核心架构](../09-Google-TPU/notes/07-tpu-arch-core.md)，观察 TPU 为什么从 INT8 走到 BF16，以及 MXU 的乘加器位宽为什么在流片时固定。

## 口径卡

| 项目 | 数字 / 口径 | 来源与提醒 |
|------|-------------|------------|
| FP32 | 1 符号 + 8 指数 + 23 尾数，bias 127 | IEEE 754 binary32；约 7 位十进制有效数字 |
| FP16 | 1 + 5 + 10，bias 15 | IEEE 754 binary16；最大有限值 65504，范围较窄 |
| BF16 | 1 + 8 + 7，bias 127 | 非 IEEE 754 独立格式；指数范围与 FP32 相同，尾数更短 |
| TF32 | 1 + 8 + 10 | NVIDIA 内部格式，不是通用 IEEE 类型；常作为 FP32 的矩阵乘替代 |
| FP8 E4M3 / E5M2 | 1 + 4 + 3 / 1 + 5 + 2 | OCP/NVIDIA 低精度格式；E4M3 最大 448，E5M2 最大 57344 |
| FP4 E2M1 | 1 + 2 + 1 | 必须配合块缩放（block scaling）；最大正规数仅 6 |
| H100 峰值 | FP16/BF16 dense 989 TFLOPS；FP8 dense 1,979 TFLOPS | SPECS §1；同一芯片、dense、Tensor Core 口径 |
| B200 峰值 | FP8 dense 4,500 TFLOPS；FP4 dense 9,000 TFLOPS | SPECS §1；厂商口径，不能与 H100 直接横比 |
| Tensor Core K 维 | TF32 K=8；FP16/BF16 K=16；FP8 K=32 | 06-12；同一输出 tile 下，K 维翻倍对应每指令 MAC 翻倍 |
| 累加精度 | 低精度浮点输入通常 FP32 累加；INT8/INT4 输入通常 INT32 累加 | 06-12；输入精度 ≠ 累加精度 |
| 元素吞吐 | H100 3.35 TB/s 下，FP16 约 1.68 T elem/s，FP8 约 3.35 T elem/s，FP4 约 6.7 T elem/s | 06-12；理论值，不含转换与访问开销 |
| 乘法器成本 | INT8 乘法器面积/能耗约为 FP32 的 1/18 | Horowitz 45nm 量级参考；不是所有工艺的固定比例 |
| dense / sparse | 未注明默认 dense；2:4 稀疏峰值通常为 dense 的 2 倍 | SPECS 使用建议；不要把两者放在同一列比较 |

## 常见误区

1. **“BF16 尾数比 FP16 少，所以 BF16 精度更差。”**
   BF16 的指数位与 FP32 相同，动态范围大得多；训练中范围溢出往往比尾数少几位更致命。选型要看任务对范围还是对有效精度的敏感度。

2. **“FP8/FP4 直接把 FP32 截断就行。”**
   E4M3 最大只有 448，E2M1 最大只有 6，必须配合 per-tensor、per-channel 或块缩放；否则真实激活值根本表示不了。FP4 还依赖 MXFP4/NVFP4 这类块缩放硬件。

3. **“低精度一定更快。”**
   只有计算受限（compute-bound）时，低精度峰值才容易转化为速度；memory-bound kernel 的收益主要来自每元素字节数减少。格式转换、解包和缩放本身也有开销，可能让低精度反而更慢。

4. **“Tensor Core 标称峰值就是实际性能。”**
   峰值是硬件上限；实际性能受 tile 形状、占用率、带宽、编译质量和累加精度影响，常用 MFU 衡量，通常显著低于 100%。

5. **“所有 GPU 的 FP64 比例都一样。”**
   H100 SXM 的 FP64:FP32 约为 1:2，RTX 4090 约为 1:64；这是产品分级和单元数量差异，不是“GPU 不擅长双精度”的一句话能解释的。

6. **“NF4 是 Blackwell 的硬件格式。”**
   NF4 是软件量化格式（QLoRA/bitsandbytes）；Blackwell 的硬件低精度格式是 FP4/FP6，两者不要混用。
